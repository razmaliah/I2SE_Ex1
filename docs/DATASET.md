# Data Set

NRRD files are large (up to 63 MB), so they are not committed to git (see `.gitignore`).
Place them in `data/` to run the demo and the experiment. Small synthetic volumes for the tests
are generated by code and are not stored at all.

## 1. Main data set

| File | Size (voxels) | Voxel type | Voxel spacing (mm) | Source |
|---|---|---|---|---|
| `MRHead_1.nrrd` | 256 × 256 × 130 | `short` (signed 16 bit) | 1 × 1 × 1.3 | 3D Slicer sample data, recommended by the lecturer |
| `croissant.nrrd` | 500 × 500 × 500 | `uint8` | 0.37 × 0.37 × 0.37 | Class data set |
| `onion.nrrd` | 256 × 256 × 130 | `uint8` | 0.55 × 0.55 × 0.715 | Class data set |
| `biscuit_cake.nrrd` | 256 × 256 × 130 | `uint16` | 1 × 1 × 1.3 | Class data set |
| `swiss_roll.nrrd` | 256 × 256 × 130 | `uint32` | 1.1 × 1.1 × 1.43 | Class data set |

**Class data set:** at the lecturer's request, the class prepared a shared set of volumes and
plane lists for all students. These files were prepared by a classmate, apparently as synthetic
volumes generated with AI tools; they are not real scans.

**Why this set covers the requirements:**

| Need | Covered by |
|---|---|
| All voxel types (FR-2) | `uint8`, `uint16`, `uint32` and signed `short` |
| Signed values, black outside the volume (FR-2, FR-13) | `MRHead_1.nrrd` |
| Performance on 500³ (NFR-1) | `croissant.nrrd`, exactly the size of the requirement |
| Non-cubic voxels (FR-7 limitation) | `MRHead_1`, `onion`, `biscuit_cake`, `swiss_roll` (z spacing 1.3 × x spacing) |
| Real anatomy for the experiment | `MRHead_1.nrrd` |

## 2. Plane lists (CSV)

| File | Planes | Content | Source |
|---|---|---|---|
| `lecturer_example.csv` | 4 | Two triangles and two trapezoids, one of them invalid (not isosceles) | Lecturer |
| `head.csv` | 280 | Sweeps through `MRHead_1.nrrd`: axis-aligned rectangles and oblique planes | Class data set |
| `croissant.csv` | 100 | Triangles through `croissant.nrrd`, partly outside the volume | Class data set |
| `onion.csv`, `biscuit_cake.csv`, `swiss_roll.csv` | 120 each | The same plane sweep for the three 256 × 256 × 130 volumes | Class data set |
| `demo/edge_cases.csv` | – | Edge cases and invalid planes, each with the result our SRS expects | Ours |

Our own files (CSV files and synthetic volumes) are created whenever a case is not covered by
the files above.

## 3. Synthetic test volumes

Generated by the tests, so every expected image is known in advance:

| Volume | Purpose |
|---|---|
| Coordinate volume: each voxel stores its own position (e.g. `x·10000 + y·100 + z`) | Every pixel tells exactly which voxel it came from, so sampling and orientation can be checked pixel by pixel |
| A solid box inside an empty volume | Shape of the image: edges, margins, parts outside the volume |
| Random values, 8 / 16 / 32 bit, signed and unsigned | Fast algorithm against the reference algorithm (NFR-2) |
| A random 500³ `uint8` volume | Performance, in addition to `croissant.nrrd` |
| Tiny volumes (1 × 1 × 1, 1 × 5 × 1) | Smallest sizes allowed (FR-3) |

## 4. Getting the files

- `MRHead_1.nrrd`: 3D Slicer → *Sample Data* → *MRHead*, or from the course materials.
- Class data set: the shared course folder.
- Synthetic volumes: created automatically when the tests run.
